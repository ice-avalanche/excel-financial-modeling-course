# Power Query: импорт и очистка данных

На первом учебном дне мы строили надежную архитектуру Excel-книги и разбирали поведение формул. Теперь переходим к слою данных.

Power Query используется там, где задача формулируется примерно так:

**«Взять данные из источника и воспроизводимо привести их к состоянию, пригодному для дальнейших расчетов».**

Главное отличие от ручной обработки состоит не в наборе команд очистки. Power Query сохраняет **последовательность преобразований**, а затем применяет ее повторно к новой выгрузке.

> [!NOTE]
> Раздаточный Excel-файл в этом занятии является источником данных, а не рабочей книгой. Его не следует редактировать. Создайте новую пустую книгу Excel и импортируйте данные из исходного файла через Power Query.

Для занятия требуется Excel 2021 или Microsoft 365 под Windows. Power Query уже встроен в эти версии и не требует отдельной установки.

## 1. Короткий разбор предыдущего домашнего задания

Перед началом Power Query полезно восстановить четыре положения предыдущего занятия.

### Ошибка #ПЕРЕНОС!

Если динамическая формула УНИК или ФИЛЬТР возвращает `#ПЕРЕНОС!`, область будущего развертывания занята. Необходимо освободить ячейки, в которые должен попасть результат.

### Несколько условий в ФИЛЬТР

Для поэлементного объединения условий используется массивная арифметика:

```excel
(условие1)*(условие2)
```

Функция И сворачивает массив в одно логическое значение и потому не подходит для построчного фильтра.

### LET должна завершаться выражением результата

В LET после пар «имя – значение» обязательно указывается последнее выражение, которое функция возвращает.

```excel
=LET(
    выручка; ...;
    количество; ...;
    выручка/количество
)
```

### Волатильные функции ищутся не только визуально

При диагностике книги используйте `Ctrl+F` с поиском по формулам и по всей книге. В частности, следует искать СМЕЩ и ДВССЫЛ.

После этого переходим к новой теме.

## 2. Место Power Query в архитектуре книги

На занятии 1.1 книга была разделена на четыре слоя:

1. данные;
2. предпосылки;
3. расчеты;
4. представление.

Power Query относится прежде всего к **слою данных**.

Он принимает первичные сведения в том виде, в каком они поступили из внешнего источника, и преобразует их в устойчивую структуру для дальнейшего использования.

### Ручная очистка и запрос – не одно и то же

При ручной обработке можно:

- удалить служебную шапку;
- исправить форматы;
- удалить итоговые строки;
- привести названия к единому виду;
- перестроить структуру таблицы.

Результат будет сохранен, но последовательность действий обычно останется только в памяти пользователя.

Через месяц приходит новая выгрузка – и работа выполняется заново.

Power Query сохраняет не только полученный набор данных, а **способ его получения**.

> [!NOTE]
> Ключевой принцип занятия: **Power Query сохраняет способ обработки, а не только ее результат.**

Именно поэтому качество запроса оценивается не по тому, обработал ли он сегодняшнюю выгрузку, а по тому, сможет ли он выполнить те же действия на следующей.

### Где использовать Power Query, формулы и VBA

**Формулы** – вычисляют показатели на уже подготовленных данных.

**Power Query** – импортирует, очищает, преобразует структуру и объединяет источники.

**VBA** – автоматизирует действия, которые не выражаются удобно ни запросом, ни формулой.

Практический ориентир:

- «взять данные оттуда и привести их к такому виду» – Power Query;
- «посчитать на основании подготовленных данных» – формулы или модель данных;
- «выполнить последовательность действий интерфейса, которую нельзя выразить предыдущими средствами» – возможная задача VBA.

```quiz
question: Что является главным преимуществом Power Query по сравнению с ручной очисткой одной выгрузки?
A: Power Query всегда выполняет вычисления быстрее обычных формул
B: Power Query сохраняет последовательность преобразований и позволяет повторно применить ее к новым данным
C: Power Query автоматически исправляет любые ошибки источника без настройки
D: Power Query полностью заменяет формулы и VBA
correct: B
explanation: Ценность запроса состоит в воспроизводимости: однажды описанная последовательность шагов может быть повторно применена при обновлении источника.
```

## 3. Импорт и устройство редактора запросов

### Исходный файл не редактируем

Создайте **новую пустую книгу Excel**.

Далее:

1. откройте вкладку **«Данные»**;
2. выберите **«Получить данные»**;
3. **«Из файла»**;
4. **«Из книги Excel»**;
5. укажите раздаточный файл занятия 2.1;
6. в навигаторе выберите лист **«Продажи (выгрузка)»**;
7. нажмите **«Преобразовать данные»**.

Не выбирайте «Загрузить»: эта команда поместит исходную выгрузку на лист без очистки. Для занятия необходимо открыть редактор запросов.

### Четыре основные области редактора

**Лента преобразований**

Основные вкладки – «Главная», «Преобразование», «Добавление столбца». Большинство команд интерфейса создают новый шаг запроса.

**Область запросов слева**

Содержит перечень запросов текущей книги.

**Предварительный просмотр в центре**

Показывает состояние данных на выбранном шаге.

> [!WARNING]
> Предварительный просмотр не гарантирует отображение всего источника. В больших наборах данных дефект, находящийся далеко за пределами первых строк, может быть не виден в окне редактора.

**Панель «Примененные шаги» справа**

Это основной объект работы.

Запрос следует воспринимать как последовательность операций. Щелкая по шагам сверху вниз, можно восстановить состояние данных на каждом этапе и определить момент, когда возникла проблема.

### Шаги следует называть осмысленно

Автоматические названия наподобие:

```text
Измененный тип
Измененный тип1
Измененный тип2
```

быстро делают длинный запрос нечитаемым.

Переименовывайте шаги по смыслу:

```text
Удалена служебная шапка
Отфильтрованы итоги
Стандартизованы точки
Месяцы развернуты
Установлен числовой тип
```

Это продолжение того же принципа сопровождаемости, который применялся к именованным диапазонам и формулам на первом дне.

### Строка формул и язык M

На вкладке «Вид» можно включить строку формул.

Каждый шаг запроса представлен выражением на языке **M**. В этом занятии писать M-код вручную не требуется, но полезно видеть, что действия интерфейса формируют программу преобразования данных.

Строка формул особенно полезна при диагностике: иногда причина проблемы в шаге заметна в выражении быстрее, чем в самом интерфейсе.

### Практика

Импортируйте лист «Продажи (выгрузка)», откройте редактор и осмотрите данные.

Пока ничего не исправляйте. Сначала перечислите обнаруженные особенности источника:

- служебные строки;
- лишние столбцы или строки;
- текстовые числа;
- различия в написании значений;
- заполнители вместо пропусков;
- особенности структуры таблицы.

## 4. Типы данных и локаль источника

Это один из наиболее важных разделов занятия.

### Сначала очищаем структуру

В начале выгрузки находятся четыре служебные строки, не относящиеся к данным.

Выполните:

1. «Главная» → «Удалить строки» → «Удалить верхние строки»;
2. укажите `4`;
3. выполните «Использовать первую строку в качестве заголовков».

После этого Power Query может автоматически создать шаг «Измененный тип».

**Удалите его.**

### Типизация выполняется после очистки

Автоматическая типизация происходит слишком рано – до того, как данные приведены к нормальному виду.

Общее правило:

> [!WARNING]
> Сначала очищается содержимое и структура источника, затем устанавливаются типы данных.

В рамках курса особенно важны:

- текст;
- целое число;
- десятичное число;
- дата;
- дата и время;
- логический тип.

Тип данных влияет не только на внешний вид, но и на набор допустимых операций.

### Локаль особенно важна для дат

Текст:

```text
03.04.2026
```

в русской локали интерпретируется как 3 апреля, а в американской – как 4 марта.

Опасность состоит в том, что часть дат при неверной локали может преобразоваться **без ошибки, но неправильно**.

Это тот же класс риска, который обсуждался ранее: молчаливо неверный результат.

### Числа, которые выглядят как числа

В столбцах месяцев встречаются значения вида:

```text
1 240 500,00
```

Внешне это число, но источник может передать его как текст.

При преобразовании возникают две отдельные проблемы.

#### Неразрывный пробел

Разделителем тысяч может оказаться не обычный пробел, а неразрывный.

Визуально они почти неразличимы, поэтому ручной ввод обычного пробела в операции замены может ничего не изменить.

Практический прием: скопировать исходное значение из ячейки, вставить его в поле замены и оставить только фактически использованный разделитель.

В отдельных строках также может присутствовать символ валюты, который требуется удалить перед типизацией.

#### Десятичный разделитель

Запятая является частью правил локали источника.

Нежелательный путь – глобально заменять запятые точками.

Корректный путь:

1. «Тип данных»;
2. «Использовать локаль»;
3. тип – «Десятичное число»;
4. локаль – **«Русский (Россия)»**.

> [!NOTE]
> Мы не переписываем сами значения под ожидания Excel. Мы сообщаем Power Query, по каким правилам следует интерпретировать источник.

### Смешанный столбец

В одном столбце часть значений может быть текстом, а часть – настоящими числами.

До типизации такой столбец ведет себя непредсказуемо в преобразованиях. После корректного приведения к типу различие устраняется.

Смешанные типы особенно критичны для будущего построения связей в модели данных.

### Заполнители отсутствующих значений

В выгрузках встречаются текстовые значения:

```text
-
н/д
```

Они обозначают отсутствие данных и при типизации могут давать ошибку.

Их следует заменить на **null**, а не на ноль.

Различие принципиально:

- `0` – значение известно и равно нулю;
- `null` – значение отсутствует или неизвестно.

Это влияет на средние значения, количество наблюдений и последующие расчеты.

### Практика

Доведите запрос до следующего состояния:

1. удалены четыре верхние служебные строки;
2. первая строка назначена заголовками;
3. преждевременный автоматический шаг типизации удален;
4. удалены мешающие числовому преобразованию символы;
5. заполнители `-` и `н/д` преобразованы в null;
6. числовые значения приведены к типу с указанием локали источника.

```quiz
question: Почему значения «н/д» и «-», обозначающие отсутствие данных, не следует автоматически заменять нулем?
A: Power Query не умеет хранить нулевые значения
B: Ноль и отсутствие значения имеют разный смысл и по-разному влияют на агрегации
C: Ноль автоматически превращает столбец в текстовый
D: Null используется только для дат
correct: B
explanation: Ноль означает известное нулевое значение, а null – отсутствие информации. Подмена одного другим меняет смысл данных и может исказить средние и другие показатели.
```

## 5. Очистка и стандартизация значений

После типизации необходимо привести строки и текстовые значения к единому виду.

Это критично для следующих занятий:

- на 2.2 данные будут объединяться со справочниками;
- на 3.1 по ним будут строиться связи в модели данных.

Значения, которые визуально кажутся одинаковыми, могут не совпадать технически.

### Удаление служебных строк

В выгрузке присутствуют:

- промежуточные строки «Итого по ...»;
- полностью пустая строка;
- повторная шапка таблицы в середине массива.

Пустые строки удаляются командой «Удалить пустые строки».

Промежуточные итоги лучше удалять не ручным выбором конкретных значений, а условием:

```text
Торговая точка не начинается с "Итого"
```

Повторная шапка исключается по значению «Торговая точка».

### Работающее решение и воспроизводимое решение

Если снять флажки только с известных сегодня значений:

```text
Итого по Северо-Западу
Итого по Уралу
```

запрос обработает текущий файл.

Но если в следующей выгрузке появится:

```text
Итого по Центральному
```

такой фильтр его не исключит.

Условие «не начинается с "Итого"» устойчиво к появлению новых регионов.

> [!NOTE]
> На занятии различаются два уровня качества: решение, которое работает на текущем файле, и решение, которое воспроизводимо на следующей выгрузке. Для регулярной отчетности важен второй уровень.

### Стандартизация текстовых значений

В столбце «Торговая точка» одна и та же точка может встречаться:

- в разном регистре;
- с пробелом в конце;
- с двойным пробелом;
- с неразрывным пробелом.

Рекомендуемая последовательность:

1. «Преобразование» → «Формат» → **«Обрезать»**;
2. **«Очистить»**;
3. заменить неразрывный пробел на обычный;
4. привести регистр к единому виду, например **«Регистр каждого слова»**.

Тот же подход применяется к категориям.

> [!WARNING]
> Команда «Обрезать» не решает все проблемы пробелов. Она не гарантирует удаление неразрывных пробелов и не исправляет любые внутренние двойные пробелы. Значения могут выглядеть одинаково и при этом не совпадать при объединении таблиц.

### Удаление дубликатов

Дубликаты удаляются **после стандартизации**, а не до нее.

До нормализации:

```text
Точка №1 Центр
точка №1 центр
```

для Power Query являются разными значениями.

Общее правило:

**сначала привести значения к единому виду, затем сравнивать, сопоставлять и удалять дубликаты.**

### Столбец из примеров

Команда «Добавление столбца» → «Столбец из примеров» позволяет показать Power Query несколько желаемых результатов, после чего система выводит правило преобразования.

Инструмент полезен для:

- извлечения фрагмента текста;
- разделения строки;
- объединения столбцов;
- простых преобразований дат.

Но полученное правило необходимо проверить.

> [!NOTE]
> «Столбец из примеров» выводит правило по нескольким образцам. Оно может соответствовать первым строкам и оказаться неверным на следующих. Проверяйте результат и выражение шага.

### Практика

1. удалите пустые строки;
2. отфильтруйте промежуточные итоги воспроизводимым условием;
3. удалите повторную шапку;
4. стандартизируйте столбец «Торговая точка»;
5. стандартизируйте столбец «Категория».

## 6. От широкого формата к длинному: unpivot

Исходная выгрузка представлена в широком формате:

```text
Торговая точка | Категория | Январь | Февраль | Март
```

Такой вид удобен для чтения человеком, но плохо подходит для регулярной обработки.

При появлении апреля требуется добавить новый столбец. Это означает изменение структуры таблицы.

Любые формулы, сводные таблицы, связи и запросы, рассчитанные на фиксированный набор месяцев, могут потребовать ручного пересмотра.

### Длинный формат

После преобразования:

```text
Торговая точка | Категория | Месяц | Сумма
```

Новый период добавляет строки, а не столбцы.

Структура остается прежней.

Рабочее правило курса:

**храним и обрабатываем данные в длинном формате, а широкое представление формируем на этапе отчетности.**

### Отменить свертывание столбцов

Первый способ:

1. выделить столбцы месяцев;
2. «Преобразование»;
3. «Отменить свертывание столбцов».

Power Query создаст:

- «Атрибут»;
- «Значение».

Переименуйте их:

```text
Месяц
Сумма
```

### Отменить свертывание других столбцов

Более устойчивый способ:

1. выделить идентифицирующие столбцы, например «Торговая точка» и «Категория»;
2. выбрать **«Отменить свертывание других столбцов»**.

Разница становится видна при поступлении новой выгрузки.

Если явно перечислены январь, февраль и март, апрель не попадет в старый перечень автоматически.

Если зафиксировано только то, какие столбцы **не нужно разворачивать**, любой новый месяц будет включен в преобразование.

> [!NOTE]
> «Отменить свертывание других столбцов» – пример воспроизводимого решения: оно описывает роль столбцов, а не сегодняшний список месяцев.

### Контроль результата

После очистки основной выгрузки должно остаться:

- **11 содержательных строк** до unpivot;
- **33 строки** после преобразования трех месяцев;
- **4 строки с пустой суммой**.

Контроль количества строк – простой способ проверить, что преобразование не потеряло и не добавило данные.

### Практика

Выполните оба варианта unpivot, сравните шаги, затем оставьте более устойчивый вариант «Отменить свертывание других столбцов».

Переименуйте столбцы и проверьте количество строк.

```quiz
question: Почему для регулярной выгрузки предпочтителен вариант «Отменить свертывание других столбцов»?
A: Он всегда выполняется быстрее любого другого преобразования
B: Он фиксирует идентифицирующие столбцы, поэтому новые месяцы автоматически попадают в длинный формат
C: Он автоматически удаляет строки с null
D: Он превращает все столбцы в текст
correct: B
explanation: Воспроизводимый запрос должен выдерживать появление нового периода. Фиксация сохраняемых столбцов позволяет автоматически развернуть новые месяцы, которых не было при создании запроса.
```

## 7. Воспроизводимость, обновление и диагностика ошибок

После завершения преобразований результат можно загрузить в книгу.

### Закрыть и загрузить

Команда **«Закрыть и загрузить»** помещает результат на лист Excel как структурированную таблицу.

Команда **«Закрыть и загрузить в...»** позволяет выбрать другой режим, в том числе:

```text
Только создать подключение
```

В этом случае данные не занимают лист.

Такой способ понадобится при работе с моделью данных: таблица фактов может содержать больше строк, чем допускает обычный лист Excel.

### Обновление на следующей выгрузке

В исходном файле есть лист **«Продажи апрель»**.

Он представляет следующий период той же системы: структура и характер дефектов похожи, но данные другие.

После смены источника на апрельскую выгрузку сохраненная последовательность Power Query должна примениться повторно.

То, на что при первой настройке ушло значительное время, при обновлении выполняется автоматически.

> [!NOTE]
> Содержательный итог занятия: ценность Power Query не в том, что запрос один раз очистил данные. Ценность в том, что он сможет очистить следующую выгрузку той же процедурой.

### Настройки обновления

Через «Данные» → «Запросы и подключения» → «Свойства» можно управлять поведением обновления.

Полезные параметры:

- обновлять при открытии файла;
- обновлять через заданный интервал;
- сохранять или удалять старые данные при неудачном обновлении.

Автоматическое обновление при открытии удобно, но на больших или сетевых источниках может замедлять запуск книги.

Сохранение предыдущих данных при неудачном обновлении тоже имеет две стороны:

- лучше старые данные, чем полностью пустой отчет;
- старые данные могут быть ошибочно восприняты как текущие.

Компромисс – явно показывать **дату последнего успешного обновления**.

### Ошибка в ячейке

Если отдельное значение не удалось преобразовать, в предварительном просмотре может появиться `Error`.

Не следует сразу удалять такую строку.

Щелкните по ошибке и установите ее причину. Ошибка может указывать на реальный дефект источника.

### Ошибка шага

Если шаг обращается к столбцу, которого больше нет или название которого изменилось, запрос может остановиться полностью.

Типичная причина – изменение структуры источника.

### Как искать место возникновения проблемы

Не начинайте анализ с последнего шага.

Последовательно щелкайте шаги **сверху вниз** и найдите первый момент, когда данные перестали соответствовать ожидаемому состоянию.

Ошибка часто возникает раньше, чем становится видимой.

### Практика

1. загрузите результат;
2. переименуйте шаги запроса осмысленно;
3. переключите источник на «Продажи апрель»;
4. выполните обновление;
5. убедитесь, что для новой выгрузки не потребовалась ручная правка шагов.

## Использование ИИ: разбор шага Power Query и M-кода

Power Query позволяет выполнять основную работу через интерфейс, но каждый шаг фактически представлен выражением языка M. Языковая модель может помочь разобрать незнакомый шаг или длинную цепочку преобразований.

Пример запроса:

```prompt
Ниже приведен M-код шага Power Query:

[ВСТАВЬТЕ КОД ШАГА]

1. Объясни, что делает этот шаг простыми словами.
2. Укажи, какой объект является входом и что получается на выходе.
3. Перечисли столбцы, типы данных и значения, на которые опирается преобразование.
4. Отметь места, чувствительные к:
   - изменению названий столбцов;
   - локали;
   - null;
   - текстовым и числовым типам;
   - появлению новых категорий или периодов.
5. Объясни, является ли шаг воспроизводимым для следующей выгрузки той же системы.
6. Если предлагаешь изменить M-код, не меняй смысл обработки и отдельно перечисли, что нужно проверить после изменения.
```

ИИ полезен как средство чтения и первичной диагностики, но не как источник гарантированно правильного M-кода.

После любого предложенного изменения необходимо:

1. пройти по шагам запроса;
2. сравнить количество строк до и после изменения;
3. проверить типы данных;
4. проверить null и ошибки;
5. обновить запрос на следующей выгрузке;
6. убедиться, что контрольные показатели не изменились необъяснимо.

## 8. Итоги занятия

После занятия необходимо зафиксировать семь положений:

1. Power Query сохраняет последовательность обработки, а не только полученный результат.
2. Типизация выполняется после очистки данных; автоматически созданный преждевременный шаг «Измененный тип» следует удалять.
3. Числовые и датовые значения интерпретируются с учетом локали источника, а не путем механической замены разделителей.
4. Текстовые заполнители отсутствия данных преобразуются в null, а не в ноль.
5. Стандартизация текста включает обрезку, очистку, обработку неразрывных пробелов и приведение регистра.
6. Широкий формат преобразуется в длинный через unpivot; для регулярных выгрузок предпочтительно «Отменить свертывание других столбцов».
7. Решение считается качественным, если оно выдерживает следующую выгрузку без ручного изменения последовательности шагов.

## Домашнее задание

Домашнее задание выполняется в новой рабочей книге с запросами. Исходный файл занятия используется только как источник.

### Часть 1. Завершение обработки – обязательная

1. Довести запрос по листу «Продажи (выгрузка)» до итогового состояния.
2. Проверить контрольные показатели:
   - 11 содержательных строк перед unpivot;
   - 33 строки после преобразования;
   - 4 строки с пустой суммой.
3. Переименовать все шаги запроса осмысленно. Названия вида «Измененный тип2» не допускаются.
4. Переключить источник на лист «Продажи апрель».
5. Выполнить обновление и убедиться, что запрос отработал без ручного изменения шагов.

### Часть 2. Реестр поступлений – обязательная

Создать отдельный запрос по листу «Поступления».

4. Преобразовать текстовые заполнители отсутствующих сумм в null.
5. Стандартизировать «Торговую точку» так, чтобы названия были совместимы со справочником.

### Часть 3. Повышенной сложности – по желанию

1. Построить отдельный запрос по листу «Справочник точек».
2. Стандартизировать значения региона.
3. После стандартизации устранить дублирующуюся запись.
4. В запросе продаж добавить проверку: сумма обработанных данных должна согласовываться с итоговыми значениями исходной выгрузки.
5. При наличии расхождения письменно объяснить его причину.
