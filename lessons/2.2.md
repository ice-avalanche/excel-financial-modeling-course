# Power Query: интеграция и автоматическое обновление данных

## 1. Добавление запросов (append)

Append применяется, когда таблицы имеют одинаковый набор столбцов, но разные строки: например, месячные выгрузки. Merge используется, когда к существующим строкам нужно присоединить атрибуты из другой таблицы.

**Append**

```excel
январь + февраль + март
```

Строк становится больше, структура столбцов сохраняется.

**Merge**

```excel
продажи + справочник точек
```

Строки сохраняются, появляются дополнительные столбцы.

Для append на курсе создается новый запрос, чтобы исходные запросы оставались неизменными.

Столбцы сопоставляются по названиям, а не по позиции. Если в одном файле поле называется «Сумма», а в другом «Сумма продаж», Power Query создаст два отдельных столбца и частично заполнит каждый. Ошибка не появится – именно поэтому несовпадение схемы опасно.

```quiz
question: Нужно объединить январь, февраль и март с одинаковым набором полей. Какая операция нужна?
A: Merge
B: Append
C: Left Anti
D: Group By
correct: B
explanation: Структура таблиц одинакова, различаются строки, поэтому используется append.
```

## 2. Слияние и типы соединения

Merge присоединяет справочные сведения к фактам по ключу. После слияния появляется столбец с вложенными таблицами, который нужно развернуть. Обычно флажок «Использовать исходное имя столбца как префикс» снимается, чтобы не получать громоздкие имена.

- **Левое внешнее** – Сохраняет все строки левой таблицы и добавляет найденные сведения. Основной рабочий вариант.
- **Внутреннее** – Оставляет только совпавшие строки. Опасно тем, что несопоставленные факты исчезают без сообщения.
- **Полное внешнее** – Сохраняет записи обеих сторон. Подходит для сверки двух равноправных источников.
- **Анти-соединение** – Возвращает строки одной стороны, которым не найдено соответствие.

После merge обязательно сверяется количество строк. Уменьшение означает возможную потерю фактов; увеличение указывает на дубликаты ключа в справочнике и размножение записей.

В учебных данных после левого внешнего соединения должно остаться 78 строк. Внутреннее соединение со справочником точек оставляет 75 – три записи исчезают.

При слиянии по двум ключам порядок выбора столбцов должен совпадать по смыслу в обеих таблицах. Если код точки и месяц указаны в разном порядке, соответствия не найдутся.

## 3. Анти-соединение как контроль

Левое anti join создает отдельный запрос, содержащий только строки, для которых не найдено соответствие в справочнике. Это гораздо надежнее визуального поиска пустых наименований после обычного merge.

В учебных данных ожидается 6 несопоставленных записей: три с кодом точки TT09 и три с кодом категории CAT7.

Аналитик не должен автоматически удалять такие строки или самовольно исправлять справочник. Решение о смысле записи принимает владелец данных; задача аналитика – сделать несоответствие явным и сохранить контроль.

> [!NOTE]
> **Аналогия.** Контрольная сумма проверяет расчет. Anti join выполняет ту же роль для полноты справочников.

```quiz
question: После merge число строк стало больше исходного. Какая причина наиболее вероятна?
A: В справочнике есть дубликаты ключей.
B: Применен left anti join.
C: Power Query удалил факты.
D: Исходные типы были текстовыми.
correct: A
explanation: Одна строка фактов сопоставляется с несколькими строками справочника и размножается по количеству совпадений.
```

## 4. Импорт всех файлов папки

Импорт из папки используется для регулярных выгрузок одной структуры. После команды «Из папки → Объединить и преобразовать данные» Power Query создает четыре объекта.

- **Образец файла** – ссылка на один файл, используемый как пример структуры;
- **Преобразовать файл** – функция, применяемая к каждому файлу;
- **Преобразовать образец файла** – запрос, в котором настраивается обработка одного файла;
- **основной запрос** – применяет функцию ко всем файлам и объединяет результаты.

Правки, которые должны выполняться с каждым файлом, вносятся именно в «Преобразовать образец файла». Изменения в основном запросе не применяются к отдельным файлам.

Столбец `Source.Name` полезно сохранить: он показывает происхождение строки и позволяет извлекать период из имени файла.

Power Query обрабатывает все файлы папки, включая временные. Поэтому сразу после источника фильтруют расширение и исключают имена, начинающиеся с `~$`.

Учебный контроль: три файла по 26 строк дают 78 строк после импорта папки.

## 5. Параметры запроса

Жестко заданный путь к папке – такой же дефект сопровождаемости, как число, зашитое в расчетную формулу. При передаче файла коллеге запрос ломается из-за другого расположения данных.

Встроенный параметр Power Query можно менять в редакторе, но для конечного пользователя удобнее таблица параметров на листе. Тогда путь, отчетный год, минимальная сумма или регион меняются обычным вводом в ячейку.

```excel
Таблица_параметров{[Параметр="Путь к папке выгрузок"]}[Значение]
```

Это первая запись языка M в курсе. По смыслу она находит в таблице строку с указанным параметром и возвращает соответствующее значение.

## 6. Контроль изменения структуры источника

В апрельской выгрузке переименованы столбцы «Код точки» и «Сумма». Если запрос обращается к старому имени, он останавливается. Такой отказ неудобен, но полезен: проблема сразу видима.

Опаснее ситуация, когда структура изменилась, а запрос продолжил работу и молча потерял часть данных. Именно так append ведет себя при несовпадающих названиях столбцов.

Можно проверять ожидаемый список столбцов, нормализовать имена сразу после источника или осознанно обрабатывать отсутствие конкретного поля.

> [!WARNING]
> **Принцип надежности.** Не требуется сделать запрос неуязвимым к любому изменению. Важно, чтобы изменение приводило к явному отказу, а не к тихому искажению результата.

## 7. Язык M и пользовательские функции

Каждое действие в интерфейсе Power Query создает выражение языка M. Полный код доступен в расширенном редакторе. Конструкция `let` объявляет последовательность именованных шагов, а `in` указывает, какой шаг возвращается как результат.

```excel
let
Источник = Excel.Workbook(File.Contents(Путь)),
Данные = Источник{[Item="Данные"]}[Data],
Заголовки = Table.PromoteHeaders(Данные)
in
Заголовки
```

Логика похожа на функцию LET из Excel: сначала объявляются промежуточные объекты, затем возвращается итог. Функция «Преобразовать файл», появившаяся при импорте папки, уже является пользовательской функцией.

## Ключевые выводы

- Append увеличивает число строк, merge – число столбцов.
- После merge количество строк обязательно сравнивается с исходным.
- Anti join следует использовать как постоянный контроль полноты справочников.
- При импорте папки преобразование отдельных файлов настраивается в образце.
- Изменяемые пути и значения должны быть параметризованы.
