# Промежуточный тест для самопроверки

Девятнадцать вопросов по материалу первых пяти дней: архитектура книги и поведение формул, подготовка данных в Power Query, модель данных и DAX, анализ чувствительности и критические значения, сценарное моделирование и стресс-тестирование.

Тест не оценивается и не ограничен по времени. Его задача – показать, какие темы стоит перечитать перед второй половиной курса. Проверять формулы в книгах при ответе не запрещается: умение найти ответ в собственной модели – тоже результат обучения.

Заголовок каждого вопроса называет тему, поэтому неверный ответ сразу указывает, к какому занятию вернуться. Карта тем приведена в конце.

> [!NOTE]
> Больше половины вопросов построены вокруг одного сквозного сюжета курса: расчет выдает неверный результат, **не сообщая об ошибке**. Если при ответе возникает мысль «но ведь Excel бы предупредил» – это и есть проверяемое место.

## Вопрос 1. Область действия имени

В книге объявлено имя `Ставка_НДС`. Формула на листе расчетов ссылается на него и возвращает ошибку `#ИМЯ?`, хотя написана без опечаток, а сама ячейка с предпосылкой заполнена.

```quiz
question: Какая причина ошибки наиболее вероятна?
A: Имя содержит подчеркивание, которое недопустимо в именах диапазонов
B: Имя создано с областью действия «лист» и недоступно с других листов книги
C: Ячейка предпосылки не отформатирована как процент
D: Имя объявлено позже, чем формула, которая на него ссылается
correct: B
explanation: При создании имени Excel предлагает выбрать область действия – книга или конкретный лист. Имя со значением «лист» не видно с других листов, а формула при этом выглядит корректно. Для предпосылок область действия всегда устанавливается на уровне книги.
```

## Вопрос 2. Обработка и сокрытие ошибок

Показатель рентабельности рассчитан формулой `=ЕСЛИОШИБКА(Прибыль/Выручка; 0)` и показывает 0 %. Выручка в книге положительна.

```quiz
question: Что следует сделать в первую очередь?
A: Оставить как есть: функция корректно обработала деление на ноль
B: Заменить ноль на прочерк, чтобы результат не вводил в заблуждение
C: Временно убрать ЕСЛИОШИБКА и выяснить, какая ошибка скрывается под нулем
D: Добавить проверку данных на ячейку выручки
correct: C
explanation: Нулевая рентабельность при положительной выручке означает, что формула обращается не к той ячейке. ЕСЛИОШИБКА применяется только к ошибкам, природа которых установлена и признана допустимой; наложенная на неисследованную формулу, она превращает видимую ошибку в невидимую.
```

## Вопрос 3. Волатильные функции и трассировка

В книге есть ячейка с формулой `=ДВССЫЛ(B20)`, где `B20` содержит текстовый адрес ячейки другого листа. Вы запускаете трассировку влияющих ячеек.

```quiz
question: Что покажет трассировка?
A: Связь с ячейкой B20 и связь с листом, на который указывает ее текст
B: Только связь с ячейкой B20; связь с фактическим источником значения не отображается
C: Ошибку, поскольку ДВССЫЛ не поддерживает трассировку
D: Полный граф зависимостей, включая все ячейки целевого листа
correct: B
explanation: Адрес источника существует только как текст и вычисляется в момент расчета, поэтому граф зависимостей его не содержит. Книга с косвенными ссылками не проверяется теми средствами, которые разбирались на занятии 1.1, – это отдельный довод против ДВССЫЛ, помимо ее волатильности.
```

## Вопрос 4. Типизация дат и локаль

В выгрузке даты записаны текстом в формате «день.месяц.год». При изменении типа столбца на «Дата» без указания локали часть значений дала ошибку, остальные преобразовались.

```quiz
question: Как оценить результат?
A: Нормально: ошибочные строки нужно удалить, остальные данные корректны
B: Опасно: преобразованные значения могут быть прочитаны как «месяц.день.год» и молча искажены
C: Нормально: Excel определяет формат автоматически по первой строке
D: Опасно: без локали даты всегда преобразуются в текущую дату
correct: B
explanation: Ошибку дали только значения с номером дня больше двенадцати – их невозможно прочитать как месяц. Остальные преобразовались по чужим правилам и теперь неверны, не подавая никаких признаков. Локаль указывается всегда, в том числе когда кажется, что и так работает.
```

## Вопрос 5. Устойчивость шага очистки

В выгрузке внутри массива данных встречаются строки промежуточных итогов: «Итого по Северо-Западу», «Итого по Уралу». Вы убираете их фильтром в Power Query.

```quiz
question: Какой способ фильтрации выдержит выгрузку следующего периода?
A: Снять галочки с конкретных значений «Итого по Северо-Западу» и «Итого по Уралу» в списке фильтра
B: Текстовый фильтр «не начинается с» со значением «Итого»
C: Удалить строки по их номерам через «Удалить строки» → «Удалить верхние строки»
D: Отсортировать таблицу так, чтобы итоги оказались внизу, и обрезать диапазон
correct: B
explanation: Фильтр по списку значений жестко фиксирует их перечень: строка «Итого по Центральному» в следующей выгрузке пройдет насквозь, а запрос отработает без ошибок. Фильтр по условию устойчив к изменению состава данных. Удаление по номерам строк ломается при любом сдвиге.
```

## Вопрос 6. Выбор типа соединения

К таблице продаж из 78 строк присоединяется справочник точек. Три записи содержат код точки, которого в справочнике нет.

```quiz
question: Что произойдет при внутреннем соединении (inner join)?
A: Запрос остановится с ошибкой о несопоставленных записях
B: Останется 78 строк, в трех из них наименование точки будет пустым
C: Останется 75 строк: три записи исчезнут без какого-либо сообщения
D: Три записи будут продублированы по всем строкам справочника
correct: C
explanation: Внутреннее соединение возвращает только сопоставленные записи и делает это молча. Поэтому рабочим типом является левое внешнее: оно сохраняет все факты, а отсутствие справочных данных становится видимым как пустое значение. Полнота справочника проверяется отдельным запросом с анти-соединением.
```

## Вопрос 7. Зерно таблицы фактов

Таблица `FactSales` имеет зерно «одна точка × одна категория × один месяц». В нее по ошибке добавлены строки, содержащие месячные итоги по точке в целом.

```quiz
question: Как это проявится в отчетах?
A: Никак: итоговые строки будут отфильтрованы моделью автоматически
B: Выручка будет завышена примерно вдвое, при этом формулы и связи останутся корректными
C: Связь с DimStore перестанет создаваться из-за нарушения уникальности
D: Сводная таблица выдаст ошибку о несовпадении уровня детализации
correct: B
explanation: Модель не знает, что часть строк является агрегатом: для нее это обычные факты, которые складываются с детальными. Нарушение зерна не вызывает ни ошибок, ни предупреждений – проверяется оно только пересчетом контрольного итога и сверкой количества строк.
```

## Вопрос 8. Вычисляемый столбец и срез отчета

В модели создан вычисляемый столбец «Прибыль строки» и мера «Валовая прибыль». Пользователь выбирает в срезе один регион.

```quiz
question: Что произойдет со значениями вычисляемого столбца?
A: Столбец пересчитается с учетом выбранного региона
B: Значения столбца не изменятся: они рассчитаны при обновлении модели и хранятся в строках
C: Столбец вернет ошибку, поскольку контекст фильтра для него не определен
D: Столбец пересчитается только при повторном обновлении источника данных
correct: B
explanation: Вычисляемый столбец получает значение в контексте строки один раз – при расчете модели – и хранится в таблице. Фильтры отчета влияют на то, какие строки попадут в агрегат, но не на сами хранимые значения. Мера, напротив, вычисляется заново для каждой ячейки отчета.
```

## Вопрос 9. Неполный справочник в модели данных

В сводной таблице, построенной из модели данных, рядом с тремя регионами появилась группа «(пусто)».

```quiz
question: Что это означает?
A: В таблице фактов есть строки с ключом, которого нет в справочнике измерения
B: В справочнике есть точки, по которым не было продаж
C: Связь между таблицами создана с неверным направлением фильтрации
D: В сводную попало поле из таблицы фактов вместо поля измерения
correct: A
explanation: Строки факта с ключом, отсутствующим в справочнике, не относятся ни к одному его значению и собираются в отдельную группу. Это та же проблема, что обнаруживалась анти-соединением на занятии 2.2, – но здесь она становится видимой уже в отчете. Точки без продаж, наоборот, дали бы строку справочника с пустым значением показателя.
```

## Вопрос 10. Соединение в запросе или связь в модели

Таблица продаж содержит код точки, а наименование, регион и формат хранятся в отдельном справочнике. Оба набора загружаются в книгу.

```quiz
question: В каком случае оправдано присоединять справочник слиянием в Power Query, а не связью в модели данных?
A: Всегда: слияние выполняется быстрее любой связи
B: Когда справочные поля нужны для дальнейших преобразований самого запроса – например, как условие фильтрации или группировки
C: Когда в справочнике больше пяти столбцов
D: Никогда: связь в модели данных полностью заменяет слияние
correct: B
explanation: Если справочное поле требуется внутри подготовки данных, его нужно иметь в таблице запроса. Если же оно нужно только как разрез отчета, слияние копирует значения в каждую строку факта без необходимости, и правильнее построить связь. Решение определяется тем, где поле используется.
```

## Вопрос 11. Размещение таблицы данных

Вы собираете блок анализа чувствительности на отдельном листе отчетности, а расчетная модель находится на другом листе.

```quiz
question: Что произойдет при попытке построить таблицу данных?
A: Таблица построится: ограничений на размещение нет
B: Excel откажется: таблица данных должна находиться на одном листе с ячейкой подстановки
C: Таблица построится, но будет пересчитываться только вручную по F9
D: Excel предложит автоматически перенести входную ячейку на лист с таблицей
correct: B
explanation: Таблица данных и входная ячейка должны быть на одном листе; формула результата при этом может ссылаться на расчет другого листа. Поэтому в учебных книгах предпосылки и области чувствительности размещены вместе, а пятилетний расчет вынесен отдельно.
```

## Вопрос 12. Проценты и процентные пункты

Ставка дисконтирования изменена с 15 % до 17 %.

```quiz
question: Какое описание изменения корректно?
A: Ставка выросла на 2 %
B: Ставка выросла на 2 процентных пункта, что составляет примерно 13,3 % относительного изменения
C: Ставка выросла на 13,3 процентных пункта
D: Обе формулировки – «на 2 %» и «на 2 п.п.» – равнозначны
correct: B
explanation: Разность двух величин, выраженных в процентах, измеряется в процентных пунктах. Относительное изменение самой ставки составляет 2 / 15 ≈ 13,3 %. Величины в рублях и натуральных единицах изменяют в процентах от базы, ставки и доли – в процентных пунктах.
```

## Вопрос 13. Устойчивость рейтинга tornado

На tornado chart факторы расположены в порядке: цена, переменные затраты, объем, постоянные затраты, ставка дисконтирования, CAPEX. Для всех факторов, кроме ставки, задано отклонение ±10 %.

```quiz
question: Какое утверждение о таком графике корректно?
A: Рейтинг отражает объективную важность факторов для данной модели
B: Рейтинг показывает эффект выбранных диапазонов и изменится, если задать другие Low и High
C: Рейтинг показывает вероятность того, что фактор отклонится от базового значения
D: Рейтинг недействителен, поскольку для ставки использованы процентные пункты
correct: B
explanation: Tornado ранжирует величину эффекта при заданных шоках. Расширив диапазон по CAPEX до ±40 %, вы поднимете его в списке, ничего не изменив в самой модели. Смешение процентов и процентных пунктов при этом допустимо, но должно быть названо: график сравнивает бизнес-шоки, а не математическую чувствительность.
```

## Вопрос 14. Возможности двухфакторной таблицы

Требуется показать, как при разных сочетаниях цены и переменных затрат ведут себя одновременно два показателя – NPV и операционная прибыль последнего года.

```quiz
question: Как это реализуется средствами таблицы данных?
A: Одной двухфакторной таблицей: в угловую ячейку помещаются ссылки на оба показателя
B: Двумя отдельными двухфакторными таблицами – по одной на показатель
C: Одной двухфакторной таблицей с двумя ячейками подстановки по строкам
D: Это невозможно: таблица данных работает только с NPV
correct: B
explanation: Двухфакторная таблица рассчитывает ровно один показатель – тот, что указан в угловой ячейке: обе размерности сетки уже заняты предпосылками. Несколько выходных показателей допускает только однофакторная таблица, где рядом размещается несколько ссылок.
```

## Вопрос 15. Точка привязки прогноза

В модели факт закрыт по 2025 год, прогноз начинается с 2026. Объем 2026 рассчитан как «стартовая база × (1 + рост)», где стартовая база – отдельная ячейка со значением 80 000, скопированным из факта 2025.

```quiz
question: Чем плоха такая конструкция?
A: Ничем: значение совпадает с фактом, расчет корректен
B: После уточнения факта 2025 прогноз продолжит считаться от устаревшей стартовой базы
C: Excel не допускает ссылок на скопированные значения в прогнозных формулах
D: Стартовая база должна быть сценарной предпосылкой, а не константой
correct: B
explanation: В книге появляются два источника одного числа. Сегодня они совпадают, поэтому дефект незаметен; при закрытии периода обновят факт, а скрытая стартовая ячейка останется прежней. Первый прогнозный год строится прямой ссылкой на последний фактический.
```

## Вопрос 16. Целостность сценария

Выбран базовый сценарий, но значение CAPEX в расчете заменено вручную на величину из оптимистичного столбца, поскольку «так ближе к реальности».

```quiz
question: Как квалифицировать полученный расчет?
A: Допустимо: это уточнение базового сценария
B: Допустимо, если изменение отмечено комментарием к ячейке
C: Модель не соответствует ни одному столбцу матрицы; воспроизвести состав предпосылок отчета невозможно
D: Недопустимо, поскольку CAPEX вообще не может быть сценарной предпосылкой
correct: C
explanation: Гибридное состояние не описывается ни одним названием и не воспроизводится. Если набор предпосылок обоснован, он оформляется отдельным сценарием с собственным названием и описанием – тогда он проверяем и повторяем.
```

## Вопрос 17. Интенсивность стресса за пределами вектора

В reverse stress testing коэффициент интенсивности `k` установлен равным 150 %.

```quiz
question: Что это означает?
A: Вероятность реализации стресса оценена в 150 %, что является ошибкой ввода
B: Предпосылки продвинуты по тому же стресс-вектору в полтора раза дальше полного стресс-теста
C: Модель рассчитана при полном стрессе, а результат умножен на 1,5
D: Значения выше 100 % недопустимы и приводят к ошибке расчета
correct: B
explanation: Активное значение считается как «база + k × (полный стресс − база)», поэтому k = 150 % продолжает тот же вектор за пределы исходно заданного теста. Коэффициент остается модельным индексом тяжести и не приобретает вероятностного смысла ни при каком значении.
```

## Вопрос 18. Постановка reverse stress testing

Руководство спрашивает: «Насколько должны ухудшиться условия, чтобы проект перестал окупаться?»

```quiz
question: Какой постановке задачи соответствует вопрос?
A: Анализу чувствительности: нужно построить таблицу данных по каждому фактору
B: Сценарному моделированию: нужно описать пессимистичный сценарий
C: Reverse stress testing: задан неприемлемый результат, ищутся условия его возникновения
D: Моделированию неопределенности: нужно задать распределения предпосылок
correct: C
explanation: Результат задан заранее – NPV = 0, – а искомым является интенсивность ухудшения условий. Это обратное направление по отношению к обычному стресс-тесту, который начинает с условий. Ответ обязательно сопровождается указанием KPI и порога, относительно которых найдена граница.
```

## Вопрос 19. Общий признак разобранных дефектов

Ручной ввод в формульном столбце, замена заполнителей нулями, перестановка ячеек подстановки в двухфакторной таблице, внутреннее соединение при неполном справочнике, нарушение зерна таблицы фактов, сценарный переключатель, влияющий на факт.

```quiz
question: Что объединяет все эти дефекты?

B: Все они приводят к появлению ошибок вида #ЗНАЧ! или #ССЫЛКА!
C: Все они дают неверный результат, не вызывая никаких сообщений Excel

correct: C
explanation: Это сквозной сюжет первых пяти дней. Видимая ошибка обнаруживается сама и чинится за минуты; молчаливое искажение живет в книге до внешней сверки. Поэтому курс последовательно вводит средства, которые делают такие дефекты заметными: контрольные суммы, анти-соединения, проверку базовой точки, инварианты сценарной модели.
```

## Как читать результат

Тест проверяет понимание, а не память на числа. Если вопрос вызвал затруднение, вернитесь к соответствующему занятию – таблица ниже показывает, куда именно.

| Вопросы | Тема | Занятие |
|---|---|---|
| 1–2 | Архитектура книги, именованные предпосылки, средства контроля | 1.1 |
| 3 | Поведение формул, волатильные функции, модель вычислений | 1.2 |
| 4–5 | Импорт, типизация, локаль, воспроизводимость шагов | 2.1 |
| 6, 10 | Объединение источников, типы соединения, контроль полноты | 2.2 |
| 7, 9 | Таблица фактов, зерно, связи, полнота справочников | 3.1 |
| 8 | Меры, вычисляемые столбцы, контекст строки и фильтра | 3.2 |
| 11–13 | Таблицы данных, диапазоны, эластичность, tornado chart | 4.1 |
| 14 | Двухфакторная чувствительность, критические значения | 4.2 |
| 15–16 | Факт и прогноз, сценарная матрица, переключатель | 5.1 |
| 17–18 | Стресс-тестирование, стресс-вектор, поиск условий отказа | 5.2 |
| 19 | Сквозная тема первых пяти дней | 1.1–5.2 |

Отдельно стоит перечитать занятие, если затруднение вызвали **два и более вопроса** из одной строки таблицы: это указывает не на забытую деталь, а на пропущенный принцип.

Вторая половина курса опирается на разобранное здесь напрямую. Статистический анализ и прогнозирование шестого дня работают с данными, подготовленными средствами второго дня; дашборды восьмого строятся на модели данных третьего; оптимизация и Monte Carlo девятого продолжают линию анализа устойчивости четвертого и пятого.
